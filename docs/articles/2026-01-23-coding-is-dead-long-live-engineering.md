# Coding is Dead, Long Live Engineering

**Published:** 2026-01-23  
**Source:** [View the original article on X](https://x.com/poteto/status/2014823103239749881)

<pre class="x-verbatim">Is coding dead? There&#x27;s been a lot of talk about AI killing software engineering, and SWEs rightfully lamenting the death of their favorite activity. 
Is AI good enough at coding? At the same time, I&#x27;ve also seen respected, senior engineers deride AI because it didn&#x27;t yield good results when they tried it. I want to share an alternative take that answers both these questions.
Yes, Coding is Dead
Let&#x27;s get this out the way. Coding is dead, assuming you can build Sufficiently Smart agents. 
&quot;This has been said a thousand times before, but allow me to add my own voice: the era of humans writing code is over. Disturbing for those of us who identify as SWEs, but no less true. That&#x27;s not to say SWEs don&#x27;t have work to do, but writing syntax directly is not it.&quot;  

Ryan Dahl - https://x.com/rough__sea/status/2013280952370573666
But the real question is not whether coding is dead, it&#x27;s whether you&#x27;re skilled enough to context engineer agents that write high quality code. If you are unable to, then you will see little value when using AI to ship real code in production.
Models have advanced enough that the bottleneck is no longer the model itself. It&#x27;s you, and everything around it that you provide: rules, skills, context, internal search tools, the way you prompt, and so much more. Given the right context, agents can write better code than I can, faster than I can. I&#x27;ve seen first hand, one of the best and most skilled engineers I know, teach Claude how to understand a deeply complex and difficult project, and use it to solve a bug that they&#x27;ve been stuck on for more than a year. 
The next unlock has become whether or not you can build a harness around Claude Code or Codex to make it truly work for you. Coding may be dead, but engineering is needed more than ever. Rather than see agents as our replacements, I think of them as a way to make cybernetically enhanced clones of myself and my colleagues. We can give these clones rules, skills, and context based on the knowledge and scars we&#x27;ve gained over the years designing systems and handwriting code.
In 2026, not getting value out of AI is ackshually a skill issue. And you wouldn&#x27;t be the first. All engineers (including me) who started their careers before AI must learn new skills in order to stay relevant. These are new skills we&#x27;ll be learning over time. 
I&#x27;m not going to say that you&#x27;re going to be left behind, but like any new paradigm, this requires changing mental models and perspectives. Skills can be learned with time (and they will keep evolving), but changing your perspective is the first and most important step.
The Factory Must Grow
I think Factorio is a close analogy describing what&#x27;s happening with coding. 
Up until very recently, SWEs wrote code by hand, painstakingly sweating the details and logic in order to build software. We were mining iron, copper, and stone with pickaxes. We were the artisans putting together fantastically complicated machines that now run everything.
In this analogy, AI heralds the invention of automation. AI labs invented a magical machine that can automate things that weren&#x27;t automatable before. Instead of mining with pickaxes, we can now build an agent rig that mines for us. Instead of putting together machines by hand, we can build machines that make the machines.
Long Live Engineering
Even though Factorio is a game where the goal is to automate production so you don&#x27;t have to do anything yourself, you still end up continuously refactoring, extending, and improving systems so they run smoothly and scale easily. It&#x27;s not fun if you just sit there and watch while the game plays itself. But nobody does that. Instead of manually mining ore and putting it into a furnace, you build drones and train tracks, and send rockets to different planets to setup more robots to do stuff for you.
You start to think about the higher level problems, because you&#x27;re not stuck spending all your time on implementation details. And if you mismanage things, you&#x27;ll end up with an inefficient factory that continuously breaks down and requires intervention.
This is what SWE has become. The only question is whether you will help the factory grow, or hang on to your pickaxe.
